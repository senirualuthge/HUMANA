What is HUMANA?

HUMANA is an enterprise-grade platform for deploying AI Digital Humans — photorealistic, voice-enabled AI agents — on your website, app, or kiosk. Each avatar has its own persona, knowledge base, and conversation memory, and can be embedded with a single line of code.

Under the hood, HUMANA powers conversations via a FastAPI backend, a real-time WebRTC pipeline for audio/video, and a vector database for infinite contextual recall across sessions.

Quickstart Guide

Follow these steps to go from zero to a live AI Digital Human on your site.

1

Create your account

Sign up with your email on the landing page. No credit card required on the Starter plan.

2

Run the setup wizard

The wizard walks you through naming your avatar, choosing a voice, setting a brand color, and writing the welcome message. Takes about 3 minutes.

shell
# Start the backend locally
cd your-project
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
3

Upload your knowledge base

Drop in PDFs, paste FAQ text, or point to a URL. Your avatar instantly learns your business context.

4

Embed and go live

Copy the one-line embed snippet from your dashboard and paste it before </body> on any webpage.

html
<!-- HUMANA Widget -->
<script src="https://cdn.humana.ai/widget.js"
        data-avatar-id="YOUR_AVATAR_ID"
        data-api-key="YOUR_API_KEY"></script>

Authentication

All API requests must include your secret API key in the X-API-Key header. You can generate and rotate keys from your dashboard.

http
GET /customers/ HTTP/1.1
Host: localhost:8000
X-API-Key: hum_live_sk_xxxxxxxxxxxxxxxxxxxx
⚠️
Keep your key secret

Never expose your API key in client-side JavaScript or public repositories. Use environment variables or a secrets manager.

HeaderDescriptionRequired
X-API-KeyYour secret API key. Prefix: hum_live_sk_required
Content-TypeMust be application/json for POST / PUT requestsrequired
X-Customer-IdScope requests to a specific customer accountoptional

Digital Humans

A Digital Human (avatar) is the core unit of HUMANA. Each avatar has its own name, voice model, appearance config, system prompt, and knowledge base. Avatars are scoped to a customer account.

Avatar properties

FieldTypeDescription
idstringUnique avatar identifier, auto-generated (UUID)
customer_idstringParent customer account ID
namestringDisplay name shown to end-users (e.g. "Aria")
voice_modelstringTTS voice. Options: nova, echo, alloy, shimmer
brand_colorstringHex color applied to the embed widget UI
system_promptstringPersona instructions injected into every conversation
welcome_messagestringFirst sentence spoken when a session starts
languagestringISO 639-1 code. Default: en. Supports 40+ languages
created_atdatetimeISO 8601 timestamp of avatar creation

Knowledge Base

The knowledge base determines what your avatar knows. Files are chunked, embedded, and stored in a vector database for semantic retrieval during each turn of conversation.

Supported sources

TypeFormatNotes
DocumentPDF, DOCX, TXTMax 50 MB per file. Starter: 3 files, Pro: unlimited
FAQ textPlain text (Q&A)Paste directly in the wizard or POST to /knowledge/faq
WebsiteURLCrawls up to 150 pages. Respects robots.txt
SpreadsheetCSV, XLSXBest for product catalogs and pricing tables
✅
Retrieval is automatic

HUMANA retrieves the 5 most relevant chunks from your knowledge base for every user message. No manual tagging required.

Live Sessions

A session is a real-time conversation between an end-user and an avatar. Sessions use WebRTC for audio/video and WebSocket for text fallback. Each session maintains its own turn history for context.

Session lifecycle

1

Create

POST /sessions/ with the avatar_id. Receive a session_token and WebRTC offer.

2

Connect

The widget exchanges ICE candidates with the HUMANA media server and establishes the peer connection.

3

Converse

Audio from the user is streamed to the STT engine, processed by the LLM + retrieval pipeline, and spoken back via TTS in <400ms.

4

End

DELETE /sessions/{id} or let the session auto-expire after 30 minutes of inactivity. A transcript webhook fires on close.

Embed Widget

The HUMANA embed widget is a self-contained web component that renders the avatar's video feed, handles audio I/O, and manages the session lifecycle entirely client-side.

Script tag (recommended)

html
<script
  src="https://cdn.humana.ai/widget.js"
  data-avatar-id="ava_xxxxxxxxxx"
  data-api-key="hum_pub_xxxxxxxxxxxx"
  data-position="bottom-right"
  data-theme="dark"
></script>

Configuration attributes

AttributeDefaultDescription
data-avatar-id—Your avatar's ID from the dashboard required
data-api-key—Your publishable key (prefix: hum_pub_) required
data-positionbottom-rightbottom-left | bottom-right | center
data-themedarkdark | light | auto
data-autostartfalseStart session immediately on page load
data-langenOverride display language (ISO 639-1)

JavaScript API

javascript
// Access the widget instance
const humana = window.HumanaWidget;

// Programmatically open / close
humana.open();
humana.close();

// Send a text message
humana.sendMessage("What are your opening hours?");

// Listen for events
humana.on('session:start', (e) => console.log(e.sessionId));
humana.on('message:received', (e) => console.log(e.text));
humana.on('session:end', (e) => console.log(e.transcript));

API — Customers

Customers represent the businesses using HUMANA. Each customer can own multiple avatars.

GET/customers/List all customers
POST/customers/Create a new customer account
GET/customers/{id}Retrieve a specific customer
PUT/customers/{id}Update customer details
DELETE/customers/{id}Delete customer and all associated avatars

POST /customers/ — Request body

json
{
  "business_name":  "Acme Corp",
  "owner_email":    "ceo@acme.com",
  "industry":       "Healthcare",
  "plan":           "starter"
}

API — Webhooks

HUMANA sends webhook events to a URL you configure. All payloads are signed with HMAC-SHA256 using your webhook secret.

Available events

EventDescription
session.startedFired when a user opens a session
session.endedFired on session close; includes full transcript
message.receivedFired for every user message (real-time)
lead.capturedFired when the avatar captures a name or email
crm.updatedFired when a CRM record is updated via integration

Verifying the signature

python
import hmac, hashlib

def verify_webhook(payload: bytes, sig_header: str, secret: str) -> bool:
    expected = hmac.new(
        secret.encode(),
        payload,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, sig_header)

Integrations — Salesforce

Connect your avatar to Salesforce so it can look up contacts, create leads, and log conversation notes automatically.

ℹ️
Prerequisite

You need a Salesforce Connected App with OAuth 2.0 enabled and the api + refresh_token scopes granted.

json
POST /integrations/salesforce
{
  "avatar_id":      "ava_xxxxxxxxxx",
  "client_id":      "YOUR_SF_CLIENT_ID",
  "client_secret":  "YOUR_SF_CLIENT_SECRET",
  "refresh_token":  "YOUR_REFRESH_TOKEN",
  "instance_url":   "https://yourorg.my.salesforce.com"
}

Integrations — HubSpot

Sync leads, contacts, and conversations from HUMANA into HubSpot CRM. Requires a HubSpot Private App token with crm.objects.contacts.write scope.

json
POST /integrations/hubspot
{
  "avatar_id":     "ava_xxxxxxxxxx",
  "access_token":  "pat-na1-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "pipeline_id":   "default"
}

Integrations — Shopify

Enable your avatar to look up orders, recommend products, and handle returns directly from your Shopify store.

json
POST /integrations/shopify
{
  "avatar_id":      "ava_xxxxxxxxxx",
  "shop_domain":    "yourstore.myshopify.com",
  "admin_api_key":  "shpat_xxxxxxxxxxxxxxxxxxxx"
}

Integrations — Healthcare / EMR

HUMANA is HIPAA-ready. PHI is never stored in conversation logs unless you explicitly enable audit-mode storage with a BAA in place. Supports HL7 FHIR R4 endpoints.

⚠️
BAA required

You must sign a Business Associate Agreement with HUMANA before enabling EMR integration. Contact hipaa@humana.ai.
